# 계획: 트러블슈팅 엑셀 통합 도구

기능 폴더: `specs/001-trouble-merge` · 상태: 초안 · 명세: `spec.md` · 원칙: `docs/constitution.md`

여기서부터 기술 이야기를 한다. 명세의 요구사항 ID(FR, NFR, SC)마다 어느 부분과 어느 테스트가 맡는지 아래 추적표에 적는다.

## 기술 선택과 이유

| 항목 | 선택 | 이유 |
|---|---|---|
| 실행 언어 | Python 3.13 | 이 PC에서 확인했다(Python 3.13.14). 한 가지 언어로 도구, 테스트, 훅을 모두 쓴다. |
| 엑셀 읽기·쓰기 | openpyxl 3.1.5 | 외부 패키지 1개. 표준 라이브러리만으로는 xlsx(압축된 XML)를 읽고 쓰기 어렵다. 이 PC에는 이미 설치되어 있다. |
| 표 파일 | 표준 `csv` 모듈, UTF-8 BOM | 규칙 표를 사람이 메모장과 엑셀로 열어 한 줄씩 추가한다. BOM이 있어야 엑셀에서 한글이 깨지지 않는다. |
| 테스트 | 표준 `unittest` | 추가 설치가 없다. 사내 PC 제약을 줄인다. |
| 보호 훅 | Python 스크립트 | 같은 언어로 맞춘다. 훅 경로는 `${CLAUDE_PROJECT_DIR}`로 고정한다. 차단은 종료 코드 2로만 보장한다(아래 보호 설계). |
| 버전 관리 | git | 보호 훅이 "이미 커밋된 파일인지"를 판단하는 데 쓴다. |

외부 패키지 추가는 openpyxl 하나뿐이다. 더 쓰려면 이유를 이 표에 적는다. openpyxl이 끌고 오는 `et_xmlfile`은 버전을 함께 고정한다. `defusedxml`은 설치돼 있으면 openpyxl이 XML 공격 방어에 자동으로 쓰므로 있으면 좋지만 필수로 두지 않고, 기본 방어는 입력 상한 검사(NFR-007)로 한다. 설치 파일은 사내 미러 또는 IT가 승인한 것을 쓰고 해시를 검증한다.

**실행 환경은 회사 PC에서 따로 확인한다.** 이 PC에서의 확인은 개발 환경 기준이다. 회사 PC에서 Python과 openpyxl 설치가 막히면 대안은 버전을 고정한 `uv run --with openpyxl==3.1.5 --with et_xmlfile==<고정 버전>`(사내 미러 또는 승인된 파일, 해시 검증)이고, 그것도 안 되면 언어를 다시 정한다. 위험 칸에도 적었다.

실제 엑셀은 이 저장소 안에 두지 않는다. 실제 입력(`D:\real_data`), 실제 결과(`D:\real_out`), 실제 변환표·컬럼 대응 표(`D:\real_config`)는 모두 저장소 밖 고정 폴더에 두고, 실제 경로는 회사 PC를 본 뒤 정한다. 저장소 안의 `out/`과 `config/`는 가짜 데이터 전용이다. `data/real/` 안에 두는 것은 예외적 대안이며 그 경우도 deny로 완전히 막는다. 실제 데이터에 도구를 돌리는 것은 사람이 자기 터미널에서만 한다.

## 데이터 모델

### 1. 컬럼 대응 표 `config/column_map.csv`

| 양식 | 원본 컬럼명 | 표준 컬럼 | 헤더행 | 시트 |
|---|---|---|---|---|
| A | (원본 헤더 하나) | 설비, 일자, 증상, 원인, 조치, 분류 중 하나 | 비우면 1 | 비우면 보이는 시트 전체 |

- 양식은 헤더로 판별한다. 한 양식의 원본 컬럼명이 모두 입력 헤더에 있으면 후보이고, 후보 중 컬럼 수가 가장 많은 양식을 택한다. 동점이면 '양식 모호'로 감사 결과에 보고하고 건너뛴다. 어느 양식에도 안 맞으면 그 파일은 '대응 규칙 없음'으로 감사 결과에 나온다(스토리 4의 3, FR-017). 시트가 여럿이면 시트마다 판별하고 감사에는 파일명과 시트명으로 나온다.
- 한 표준 컬럼에 원본 컬럼이 여럿 대응되면 처리하지 않고 감사에 보고한다.
- 설비 표준 컬럼에는 설비 코드 컬럼을 대응시킨다.
- 대응 표에 없는 원본 컬럼은 '기타 항목'에 `이름: 값`으로 보관한다. 감사 결과에는 컬럼명만 나온다.
- 새 양식은 이 표에 줄을 추가하면 끝난다(FR-007).

### 2. 변환 표 `config/conversion_map.csv`

| 종류 | 원래 값 | 표준 값 |
|---|---|---|
| 설비 | (설비 코드) | 표준 설비 코드 |
| 분류 | (원래 분류 이름) | 표준 분류 이름 |

- 한 표에 종류 열로 설비와 분류를 함께 둔다. 요청서의 "분류 변환표 한 개"를 지킨다.
- 원래 값과 표의 키를 모두 앞뒤 공백 제거 후 소문자로 바꿔 정확히 같을 때만 일치로 본다(FR-009, FR-018). 같은 키가 표준 값을 달리해 두 번 나오면 실행을 멈추고 줄 번호만 보고한다.
- 표에 없는 값은 '확인 필요'가 된다. 사람이 한 줄을 더하면 다음 실행부터 자동 처리된다.

### 3. 출력 통합 시트

| 컬럼 | 내용 |
|---|---|
| 설비, 일자, 증상, 원인, 조치, 분류 | 표준 컬럼. 일자는 `YYYY-MM-DD` |
| 기타 항목 | 표준에 없는 컬럼을 원본 순서대로 `이름: 값`으로 `; `로 이어 붙인 문자열. 빈 값은 생략(FR-015) |
| 확인 필요 이유 | 비어 있으면 정상 행. 있으면 이유 문구를 설비, 일자, 증상, 원인, 조치, 분류 순서로 `; `로 이음 |
| 원래 값 | '확인 필요'가 된 칸의 원래 값 `컬럼: 값`을 같은 순서와 구분자로 이음 |
| 중복 의심 | 변환 후 설비·정리한 일자·증상이 같은 행에 표시. 설비나 일자가 '확인 필요'인 행은 제외(FR-010) |
| 원본 파일, 원본 시트, 원본 행 | 추적용. 셀 값은 아니다 |

'확인 필요'가 된 칸에는 해당 칸 자체에 `확인 필요`라고 쓴다. 입력의 모든 행이 출력에 있다(FR-006, 행의 정의는 FR-014). 정렬은 설비, 일자, 원본 파일, 원본 행 순이고 설비가 '확인 필요'인 행은 맨 아래다(FR-016).

### 4. 감사 결과 `out/audit_<실행시각>.txt`

한국어 텍스트 한 장. 입력·출력 행 수와 일치 여부, 대응 규칙 없는 컬럼명, 필수값이 빈 행(행 번호와 컬럼명), '확인 필요' 건수, 숨긴 시트 수, 실패한 파일명, '대응 규칙 없음'·'양식 모호'인 파일·시트명과 그 행 수, 수식 값 없음 건수, 상한 초과·`.xlsm`·`.xls`로 건너뛴 파일과 사유 종류, 수식 방지 접두사 처리 건수를 담는다. 셀 값은 넣지 않는다. 컬럼명은 컬럼 대응 표에 등록된 이름만 그대로 쓰고 나머지는 `열 3(C)`로 쓴다(30자 상한). 파일명·시트명은 기본이 `file_01`·`sheet_01` 마스킹이고 대응표는 별도 파일로 낸다(NFR-009).

### 4-1. 실행 방법과 종료 코드 (FR-019)

`python -m trouble_merge --input <폴더 또는 파일...> --config config --out out`. 종료 코드는 0 정상, 1 일부 파일 실패, 2 전부 실패 또는 설정 오류다. 테스트는 `out/`이 아니라 임시 폴더를 출력으로 써서 출력 이름의 시각 때문에 비교가 흔들리지 않게 한다.

### 5. 처리 순서

1. 입력 파일을 하나씩 연다. `.xlsx`가 아니거나, 파일·압축 해제 후 크기·시트당 행 수가 상한을 넘거나, 열 수 없으면 건너뛰고 기록한다(상한 숫자는 구현 전에 사람이 정해 `config`에 둔다. NFR-007). 외부 링크와 매크로는 따라가지 않는다.
2. 보이는 시트를 읽는다. 숨긴 시트(`hidden`, `veryHidden`)는 읽지 않고 기록한다. 값은 `data_only=True`로 읽고, 병합 셀은 첫 칸 값을 범위에 채우며, 모든 칸이 빈 행은 입력 행에서 뺀다(FR-014).
3. 헤더로 양식을 판별하고 표준 컬럼에 옮긴다. 남은 컬럼은 '기타 항목'에 둔다.
4. 날짜, 설비, 분류, 필수값을 검사해 '확인 필요'를 표시한다.
5. 중복 의심을 표시한다.
6. 통합 엑셀과 감사 결과를 `out/`에 새 이름으로 쓴다. 이미 있으면 실행 시각을 붙인다. 문자열 셀은 항상 문자열 형식으로 쓰고 `=`, `+`, `-`, `@`로 시작하면 앞에 `'`를 붙인다(NFR-008).

## 로그

- 로그를 내는 길은 `safe_log` 하나다. 이 함수는 `종류, 파일명, 시트명, 행 번호, 컬럼명, 건수`만 받는 고정 형식이다. 자유 문장이나 셀 값 인자가 없다.
- 예외 메시지는 버리고 예외 종류만 `safe_log`로 낸다. openpyxl 예외 메시지와 날짜 해석 실패 메시지에는 셀 값이 섞일 수 있어서다. 처리되지 않은 예외도 최상위에서 같은 길로 내고, `warnings`는 무시하거나 `safe_log`로만 낸다. 날짜 해석 불가는 컬럼명과 행 번호만 낸다.
- `safe_log`은 컬럼명 인자를 받을 때 컬럼 대응 표 등록 여부를 확인해 미등록이면 위치 표기로 바꾸고, 길이를 30자로 자른다. 파일명·시트명은 마스킹 이름으로 바꾼다(NFR-009). 헤더 행을 잘못 잡아도 제목 문장이 로그에 나가지 않게 하기 위해서다.
- `tests/test_log_safe.py`: 가짜 데이터에 표식 값(`LEAK-`로 시작)을 심고, 정상 실행과 오류 실행의 로그, stderr, `warnings`에 표식 값이 없는지 본다(원칙 2, SC-004).

## 보호 설계

| 대상 | 수단 |
|---|---|
| 실제 데이터·결과·설정 | 저장소 밖 폴더 3곳(`real_data`, `real_out`, `real_config`)과 사용자 홈의 다운로드·바탕화면을 deny(Read, Grep, Glob, Bash, PowerShell). `data/real/`을 쓰는 예외 경우는 `./data/real/**`도 deny. **운영체제 권한을 병행한다**: 그 폴더를 Claude 실행 계정이 읽지 못하게 NTFS 권한을 걸거나 Claude를 별도 계정·WSL·VM에서 실행한다(사람과 IT 작업). 가짜 데이터 폴더만 예외 |
| `expected/`, `data/fake/`, `tests/`, `config/*.csv`, `.claude/settings.json`, `.claude/hooks/`, `.claude/agents/`, `docs/constitution.md`, `CLAUDE.md`, `specs/**/spec.md`·`plan.md`·`tasks.md` | PreToolUse 훅 `protect_files.py`. **Edit·Write는 이미 git에 추적되는 파일이면 차단(종료 코드 2). 아직 없는 파일은 `tasks.md`에 이름이 적힌 파일만 허용하고, 그 밖의 새 파일은 보호 폴더 안에서 차단한다.** `.claude/` 아래는 새 파일도 차단한다(`settings.local.json` 포함, 에이전트 정의는 사람이 만든다). 커밋한 뒤에는 에이전트가 못 고친다. 보호 장치 자체도 같은 규칙으로 보호한다 |
| 같은 대상에 대한 Bash·PowerShell | 같은 훅. 명령 문자열에 보호 경로가 있고 쓰기·삭제·이동 동사(`cp`, `mv`, `rm`, `del`, `ren`, `Remove-Item`, `Copy-Item`, `Set-Content`, `Out-File`, `xcopy`, `robocopy`, `curl -o`, `certutil`, `>`, `python`으로 저장 등)가 있으면 차단한다. 인터프리터 직접 실행(`python -c`, `powershell -c`, `cmd /c`)은 허용된 명령만 통과시키는 허용 목록 방식으로 한다. git 명령은 `status`, `diff`, `log`, `show`, `add`, `commit`만 허용하고 `rm`, `reset`, `restore`, `checkout -- 파일`, `stash`, `config`, `rebase`, `filter-*`, `.git/` 접근은 차단한다. 링크·정션 생성(`mklink`, `New-Item -ItemType Junction/SymbolicLink`)도 차단한다. 문자열을 피해 가는 길은 남고 운영체제 권한과 README 남은 위험으로 보완한다 |
| 규칙 표의 기존 내용 | 위와 같다. 에이전트는 추가할 줄을 제안만 하고 사람이 반영한다 |
| 완료 | 훅으로 강제하지 않는다. 완료 보고에 `python -m unittest` 결과를 붙인다(헌법 원칙 5). 실패 상태 커밋(T018 등)과 충돌하지 않게 Stop 훅은 두지 않는다 |

- 헌법 원칙 4 개정(v1.1.0)에 맞춰 deny가 아니라 훅으로 보호한다. deny는 아직 없는 파일을 만드는 것도 막기 때문이다.
- 훅 전체를 `try/except`로 감싸 입력 파싱 실패, git 실행 실패, 그 밖의 모든 예외에서 `sys.exit(2)`로 끝낸다(fail-closed). 미처리 예외는 종료 코드 1이라 차단되지 않으므로, 설정의 `onFailure` 같은 항목에 기대지 않는다.
- 경로는 `os.path.realpath`로 실제 경로를 해석한 뒤 판단한다(`..`, 역슬래시, 대소문자, 8.3 짧은 이름, 정션·심볼릭 링크, `\\?\` 접두사, UNC, 대체 데이터 스트림 `파일:스트림`, 후행 점·공백). `git add`만 하고 커밋하지 않은 파일도 추적 파일로 본다.
- 첫 커밋(T012) 직후 사람이 보호 대상 파일의 SHA-256 목록을 저장소 밖에 보관하고, 각 Phase 끝에 사람이 자기 터미널에서 대조한다(에이전트는 못 본다). 훅이 뚫려도 변경을 알 수 있는 독립 확인이다.
- `hook_test.py`: 시도 목록(Edit, Write, PowerShell 복사, Python 저장, 경로를 변수에 담기, 입력이 깨진 경우, git 실행 실패, 경로 변형, `git add`만 한 파일)을 넣고 FAIL이 0이 될 때까지 고친다.
- **한계**: 훅과 deny는 명령 문자열을 본다. 우회하는 길이 남고, 네이티브 Windows에는 샌드박스가 없다. 그래서 운영체제 권한을 병행하고(위 표), 그래도 남는 위험은 README에 적는다(원칙 1). 운영체제 권한을 걸지 못하면 실제 데이터 작업은 AI 세션이 없는 PC·계정에서만 한다.
- git 저장소가 아직 없다. 작업 단계의 첫 일로 `git init`을 한다. 첫 커밋 전에는 모든 파일이 미추적이라 훅이 막지 못하므로, 가짜 데이터와 정답과 비교 테스트를 만든 직후 커밋해서 보호를 켠다.

## 에이전트 두 개

| 이름 | 하는 일 | 도구 | 쓰지 않는 때 |
|---|---|---|---|
| format-analyst (양식 분석가) | `docs/`의 컬럼 설명 문서와 가짜 입력의 구조를 읽고 컬럼 대응 규칙 초안과 '규칙으로 판단하기 어려운 입력' 표를 `docs/proposals/`에 쓴다 | Read, Grep, Glob, Write(`docs/columns-*.md`, `docs/proposals/**`만) | 코드를 고칠 때, 실제 데이터 근처 |
| merge-auditor (감사관) | 구현을 모르는 상태로 테스트와 `out/` 결과를 읽고 통과 또는 반려로 판정한다. 반려하면 지적을 요약으로 돌려준다 | Read, Grep, Glob, Bash(테스트 실행만) | 코드를 고치려 할 때 |

두 에이전트의 경로·명령 제한은 에이전트 정의의 도구 목록만으로는 지켜지지 않는다. 구체 규칙은 다음과 같다. format-analyst는 `Write(docs/columns-*.md)`와 `Write(docs/proposals/**)`만 허용한다. merge-auditor는 `Bash(python -m unittest*)` 한 가지만 허용하고 Write·Edit는 없다. 다만 `unittest`는 `tests/`와 `src/`의 코드를 실행하므로 "읽기 전용"이 아니다. 따라서 **구현 전에 훅이 에이전트별 도구 호출을 구분할 수 있는지 먼저 시험한다**(T005a). 구분하지 못하면 두 에이전트는 파일을 쓰지 않고 초안과 판정을 대화 출력으로만 낸다. 에이전트 정의 파일은 사람이 만든다.

감사관은 Edit과 Write를 갖지 않는다. 구현을 맡은 메인 대화와 다른 맥락에서 일하고, 지적은 `docs/review.md`가 아니라 요약으로 돌려준다.

## 위험과 되돌리기

| 위험 | 대응 |
|---|---|
| 회사 PC에서 Python 또는 openpyxl이 안 됨 | `uv run --with openpyxl`을 시도. 안 되면 정보보호·IT 부서와 협의하고 언어를 다시 정한다. 코드는 읽기·쓰기를 한 모듈에 모아 교체 범위를 줄인다 |
| 첫 커밋 전에는 훅이 보호하지 못함 | 첫 비교 테스트 커밋 전까지는 사람이 지켜본다. 이후 `git status`로 확인 |
| 훅 우회로(변수, 스크립트 안 저장) | `hook_test`에 시도를 계속 추가한다. 남는 길은 README 남은 위험으로 둔다 |
| 날짜 셀이 날짜형이거나 문자열이거나 숫자 | 가짜 데이터에 세 가지를 모두 넣고 테스트한다 |

| 구현이 틀렸을 때 | Phase마다 커밋한다. 되돌리기(`/rewind`, `git restore`)는 사람이 한다(에이전트의 `git restore`·`reset`은 훅이 차단) |

| 실제 결과(`D:\real_out`) 보관·동기화 | 보관 기간을 정하고 동기화(OneDrive 등) 폴더에서 제외한다. 공유 때는 접근 권한을 확인한다. README와 T050에 적는다 |

## 구현 순서 (tasks에서 쪼갠다)

1. 가짜 데이터 양식 A(`A_basic`, `A_trap` 두 파일), 정답, 컬럼 설명 문서, 보호 훅, deny 규칙(`data/real`만), 첫 커밋.
2. 비교 테스트를 실패 상태로 커밋.
3. 어댑터 1개로 `A_basic` 통과, 이어서 Phase 4에서 `A_trap` 통과.
4. 양식 2~3종, 파일 5~8개로 확장. 매핑 표에 줄만 추가해서 처리되는지 확인.
5. 감사관 판정, 교차 의심, README와 CLAUDE.md 정리.
