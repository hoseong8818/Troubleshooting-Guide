# trouble-merge

양식이 다른 설비 트러블슈팅 엑셀 여러 개를 읽어 표준 컬럼의 통합 시트 1장으로 만들고, 감사 결과 텍스트를 함께 냅니다.

- 표준 컬럼: 설비, 일자, 증상, 원인, 조치, 분류, 기타 항목
- 감사 컬럼: 확인 필요 이유, 원래 값, 중복 의심, 원본 파일, 원본 시트, 원본 행
- 설비는 설비 코드 컬럼 기준입니다. 자유 텍스트에서 설비를 추정하지 않습니다.
- 판단이 안 되는 행은 지우지 않고 '확인 필요'로 남깁니다. 입력 행 수와 출력 행 수는 같습니다.

문서는 `docs/constitution.md`(헌법) → `specs/001-trouble-merge/spec.md`(명세) → `plan.md`(계획) → `tasks.md`(작업) 순서로 읽습니다.

## 설치

- Python 3.13 (테스트한 버전: 3.13.14)
- 외부 패키지는 `openpyxl` 하나입니다. `defusedxml`은 있으면 쓰고 없어도 됩니다.
- 버전은 `requirements.txt`에 고정했습니다: `openpyxl==3.1.5`, 그 의존 패키지 `et_xmlfile==2.0.0` (테스트를 통과한 개발 PC의 버전).

```bash
python -m pip install --require-hashes -r requirements.txt
```

- `requirements.txt`에는 두 패키지의 `.whl` 파일 SHA-256을 함께 적었습니다. 해시가 다르면 pip이 설치를 거부합니다.
- 해시는 2026-11-12에 `pip download`로 받은 파일의 값과 PyPI가 공시한 값이 같은 것을 확인해 넣었습니다. 이것은 내려받은 파일이 PyPI의 파일과 같다는 확인이지 패키지 자체의 안전을 보증하지는 않습니다.
- 미검증(2026-11-12): `--require-hashes` 설치를 새 가상환경에서 끝까지 시험한 결과는 아직 확인하지 못했습니다. 기존 환경에서는 이미 설치되어 있어 해시 검사가 실행되지 않았습니다. 데모 범위에서는 시험하지 않았고, 실제 업무 이관 시 새 PC에서 처음 설치할 때 한 번 시험하고 이 줄을 고칩니다(T050).
- 사내 미러나 IT가 승인한 파일을 쓰는 PC에서는 그 파일의 해시가 위 값과 같은지 먼저 대조합니다. 다르면 설치하지 말고 IT에 문의합니다.
- 버전을 올릴 때는 새 파일의 해시를 같은 방식으로 다시 대조해 이 파일을 고칩니다.

## 실행

```bash
python -m trouble_merge --input <파일 또는 폴더> [<더 많은 입력>] --config config --out out
```

(저장소 루트에서 `PYTHONPATH=src`로 실행합니다.)

| 인자 | 설명 |
|---|---|
| `--input` | 입력 파일이나 폴더(여러 개 가능). `.xlsx`만 읽습니다. |
| `--config` | `column_map.csv`, `conversion_map.csv`가 있는 폴더 |
| `--out` | 출력 폴더 |
| `--show-names` | 감사 결과에 파일명·시트명을 마스킹하지 않고 표시 |

### 출력 (`--out` 폴더)

| 파일 | 내용 |
|---|---|
| `merged.xlsx` | 통합 시트. 이미 있으면 덮어쓰지 않고 `merged_<실행 시각>.xlsx` |
| `audit_<실행 시각>.txt` | 감사 결과(입력·출력 행 수, '확인 필요' 건수, 건너뛴 파일·시트, 숨긴 시트 수 등) |
| `names_<실행 시각>.txt` | 마스킹 이름(`file_01`, `sheet_01`)과 실제 이름의 대응표 |

### 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 모두 정상 |
| 1 | 일부 파일·시트를 건너뜀(열 수 없음, 대응 규칙 없음, 양식 모호) |
| 2 | 전부 실패했거나 설정 오류. 통합 파일을 만들지 않음 |

## 새 양식 추가

코드를 고치지 않고 `config/column_map.csv`에 줄만 추가합니다.

- 한 양식의 원본 컬럼명이 입력 헤더에 모두 있으면 그 양식으로 판별합니다. 후보가 여럿이면 컬럼 수가 많은 쪽, 같으면 '양식 모호'로 건너뜁니다. 어느 양식에도 안 맞으면 감사 결과에 '대응 규칙 없음'.
- 표에 없는 컬럼은 '기타 항목'에 `이름: 값`으로 보관합니다.
- 설비·분류 변환은 `config/conversion_map.csv`(종류 열로 구분). 비교는 앞뒤 공백·대소문자만 정리한 뒤 정확히 같을 때만 일치로 봅니다. 같은 키에 표준 값이 둘이면 실행을 멈춥니다(종료 코드 2).
- 두 CSV는 UTF-8 BOM으로 저장합니다.

## 테스트

```bash
python -m unittest                          # 전체
python -m unittest tests.test_compare       # 모듈 하나
python .claude/hooks/hook_test.py           # 보호 훅 시험 (FAIL 0이어야 함)
```

테스트는 가짜 데이터(`data/fake/`)와 정답(`expected/`)만 씁니다. 가짜 데이터는 `python tools/make_fake_data.py [A|B|all]`로 만들며, 이미 파일이 있으면 중단합니다.

## 실제 데이터를 다룰 때의 규칙

- 실제 엑셀은 AI 도구(Claude Code 등)가 읽지 못하게 저장소 밖 고정 폴더(`real_data`, `real_out`, `real_config`)에 두고, 도구 실행은 사람이 자기 터미널에서만 합니다.
- 실제 결과 엑셀, 감사 결과, 로그, `names_*.txt`를 AI에 붙여 넣거나 첨부하지 않습니다.
- 저장소 안의 `out/`과 `config/`는 가짜 데이터 전용입니다.
- 로그와 에러 메시지에는 셀 값이 나오지 않습니다. 파일명·시트명은 기본 마스킹, 등록되지 않은 컬럼명은 `열 3(C)`처럼 위치로만 표시합니다.
- 입력 엑셀은 신뢰하지 않습니다. 출력 문자열 셀이 `=`, `+`, `-`, `@`로 시작하면 앞에 `'`를 붙여 수식 실행을 막습니다.

## 출력 보관

- **통합 시트에는 실제 파일명·시트명·셀 값이 그대로 들어갑니다.** 결과 파일은 원본과 같은 수준의 비밀로 다룹니다.
- 출력 폴더(`real_out`)는 클라우드 동기화 대상에서 제외합니다.
- 통합 시트, 감사 결과, 이름 대응표(`names_*.txt`)는 같은 기간에 함께 보관하고 함께 지웁니다.
- 보관 기간은 업무에 쓴 뒤 30일입니다. 삭제는 사람이 직접 합니다(이 도구는 자동으로 지우지 않습니다). 이름 대응표는 마스킹을 풀 수 있어 가장 먼저 지웁니다.
- 정보보호 부서의 정책이 이 값과 다르면 부서 정책을 따르고 이 문장을 고칩니다.

## 남은 위험

보호 장치(`.claude/settings.json`의 deny, PreToolUse 훅)는 문자열 검사라 완전하지 않습니다. 근거는 `docs/security-review-proposal.md`.

| 위험 | 상태 |
|---|---|
| **샌드박스가 없습니다.** 네이티브 Windows라 운영체제 격리가 없습니다. | NTFS 권한 또는 별도 계정·WSL로 보완해야 합니다(T003a). 설정 여부: 데모 범위에서는 설정하지 않음. 2026-11-12 기준 `D:\real_data` 폴더가 없습니다. 실제 업무 이관 시 폴더와 권한을 먼저 만들고(T003a), 그 전에는 실제 데이터를 이 저장소 근처에 두지 않습니다. |
| **훅 우회 가능성.** `~/.claude/settings.json`에 `disableAllHooks`가 들어가면 훅이 모두 꺼집니다. | 현재 없음. 쓰기 차단은 T005b 미적용, 관리자 설정 훅은 IT에 문의 |
| **`python -m unittest`는 임의 코드 실행 경로입니다.** 훅이 허용하는 유일한 python 실행입니다. | 커밋 전 `git diff` 검토, 운영체제 권한이 최종 방어 |
| **deny에 Grep·Glob 규칙이 없습니다.** | 추가 여부 결정 필요(사람) |
| **입력 크기·행 수 상한이 구현되지 않았습니다(NFR-007).** 압축 폭탄·거대 파일이 메모리를 쓸 수 있습니다. | 데모 범위에서는 구현하지 않음(2026-11-12 결정). 실제 업무 이관 전에 정보보호 부서에서 숫자를 정해 테스트 먼저 방식으로 구현(T003b, T050). 지금은 `.xlsm`·`.xls`만 거부 |
| **보호는 커밋 기준입니다.** 미추적 파일은 훅이 막지 못합니다. | 보호 파일 SHA-256 목록을 저장소 밖에 보관하고 Phase마다 대조 |
| **회사 PC 확인.** 실제 데이터를 돌릴 PC의 보안 정책 | 데모 범위에서는 하지 않음. 실제 업무 이관 시 T050 체크리스트로 확인 |
| **가짜 데이터와 실제 엑셀의 차이.** 헤더 행 위치, 병합 셀, 수식 계산값, 끝쪽 빈 서식 행, 설비 코드·날짜 형식은 실제 파일에서 다를 수 있습니다. | 실제 데이터 시험은 사람이 직접(T050). 처리 시간 상한(NFR-005)은 보류 |
| **일자가 없는 양식은 설비·증상만 같아도 '중복 의심'입니다.** | 확정한 결정. 실제 사용 후 노이즈 재검토 |
