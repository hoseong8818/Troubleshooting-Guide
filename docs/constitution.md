# 트러블슈팅 엑셀 통합 도구 헌법

버전 1.2.0 · 2026-11-12 · 확정 (보안 검토 `docs/security-review-proposal.md` 권장 묶음 반영)

이 도구는 설비 트러블슈팅 엑셀 여러 개를 한 표로 모으고 설비별로 분류한다.
아래 다섯 원칙은 모든 기능과 모든 작업에 적용한다.
원칙마다 근거와 검사 방법을 함께 적는다. 검사할 수 없는 원칙은 두지 않는다.

## 원칙 1. 실제 엑셀은 AI가 읽지 않는다

- **근거**: 읽은 파일 내용은 모델 요청에 실리고 로컬 대화 기록에도 남는다. 실제 데이터는 회사 PC에서 사람이 직접 돌린다. AI에게는 사람이 쓴 컬럼 설명 문서와 가짜 데이터만 준다.
- **컬럼 정보**: 가짜 데이터의 컬럼명은 실제와 같게 만든다. AI는 엑셀에 접근해 컬럼을 확인하지 않고, 사람이 직접 알려 주거나 사람이 쓴 md 파일로만 받는다. 실제 컬럼명을 AI에 알려도 되는지는 정보보호 부서 기준을 확인한다.
- **실제 데이터 위치**: 저장소 밖 고정 폴더 1곳(예: `D:\real_data`)만 쓴다. 실제 실행 결과(`D:\real_out`)와 실제 변환표(`D:\real_config`)도 저장소 밖에 둔다. 저장소 안의 `out/`과 `config/`는 가짜 데이터 전용이다. 실제 데이터에 도구를 돌리는 것은 사람이 자기 터미널에서만 한다. 팀원이 보낸 파일은 받는 즉시 위 폴더로 옮긴다. 실제 폴더 경로는 회사 PC 환경을 본 뒤 정한다.
- **검사 방법**:
  - `.claude/settings.json`의 deny에 위 실제 폴더 3곳과 사용자 홈의 다운로드·바탕화면을 넣는다. Read, Grep, Glob, Bash, PowerShell을 모두 대상으로 한다. 가짜 데이터 폴더만 예외다.
  - deny와 훅은 명령 문자열을 보는 것이라 완전하지 않다. 그래서 운영체제 권한(NTFS 권한, 또는 Claude를 별도 Windows 계정·WSL·VM에서 실행)을 함께 건다. 이것은 사람과 IT가 설정하고 설정한 날짜를 README에 적는다.
  - PreToolUse 훅을 건다. 훅 시험 스크립트에서 FAIL이 0이어야 한다.
  - 실제 데이터 폴더를 흉내 낸 가짜 폴더로 "읽어 줘"를 시도해 막히는 화면을 기록한다.
- **남는 위험**: 네이티브 Windows에는 샌드박스가 없어 명령 문자열을 피해 가는 길이 남는다. 운영체제 권한을 걸지 못하면 이 위험이 그대로 남는다. README의 남은 위험 칸에 적는다.

## 원칙 2. 로그와 에러에 셀 값을 남기지 않는다

- **근거**: 에러와 로그를 Claude에게 붙여 넣어도 데이터가 새지 않아야 한다.
- **남기는 것**: 행 번호, 컬럼명, 건수, 파일명, 시트명뿐이다. 셀 값은 로그에도 에러 메시지에도 넣지 않는다.
- **로그 형식**: 로그를 내는 길을 하나로 정하고, 그 길은 셀 값을 받지 않게 만든다. 구체적인 방법은 plan에서 정한다.
- **이름도 값이 될 수 있다**: 헤더 행을 잘못 잡으면 제목 문장이 컬럼명으로 나온다. 파일명과 시트명에 사람 이름이나 프로젝트명이 있을 수 있다. 그래서 컬럼명은 컬럼 대응 표에 등록된 이름만 그대로 내고, 등록되지 않은 컬럼은 위치(`열 3(C)`)로만 적는다. 컬럼명에는 길이 상한을 둔다. 파일명과 시트명은 마스킹(`file_01`)이 기본이고, 실제 이름을 내는 설정은 사람이 켠다.
- **검사 방법**: 가짜 데이터에 눈에 띄는 표식 값을 심어 두고, 도구를 정상과 오류 두 경우로 돌린 뒤 로그와 stderr에 표식 값이 없는지 테스트한다.

## 원칙 3. 판단이 안 되면 '확인 필요'로 남긴다

- **근거**: 설비를 규칙으로 정할 수 없는 행을 억지로 분류하면 사람이 틀린 결과를 믿는다. 정하는 것은 업무를 아는 사람이다.
- **'확인 필요'로 남기는 경우**:
  - 설비 코드가 비어 있다.
  - 설비 코드가 변환표에 없다.
  - 분류 값이 변환표에 없다.
  - 필수값이 빈 행이거나 날짜를 해석할 수 없다.
- **처리 방법**: 행을 빼지 않고 같은 통합 표에 넣는다. 해당 칸에 '확인 필요'를 쓰고, 원래 값과 이유를 함께 남긴다. 사람이 변환표에 한 줄을 더하면 다음 실행부터 자동으로 처리된다.
- **검사 방법**:
  - 위 네 경우의 행이 '확인 필요', 원래 값, 이유와 함께 출력된다.
  - 입력 행 수와 출력 행 수가 같다.
  - 감사 결과에 '확인 필요' 건수가 보고된다.
  - 이 셋을 수용 기준 테스트로 확인한다.

## 원칙 4. 정답, 입력, 테스트, 변환표는 에이전트가 수정하지 않는다

- **근거**: 정답이나 테스트가 구현에 맞춰 바뀌면 테스트는 통과해도 결과는 틀리다. 변환표를 에이전트가 임의로 고치면 분류 기준이 사람 모르게 바뀐다. 원본이 바뀌면 되돌릴 수 없다.
- **보호 대상**: `expected/`(정답), 가짜 입력 데이터 폴더, 테스트 파일, 변환표와 매핑표, 보호 장치 자체(`.claude/settings.json`, `.claude/hooks/`, `.claude/agents/`), 그리고 지시·기준 문서(`docs/constitution.md`, `CLAUDE.md`, `specs/**/spec.md`, `plan.md`, `tasks.md`). 지시 문서가 바뀌면 다음 세션의 행동이 바뀌기 때문이다.
- **예외**: 사람이 맡긴 작업에서 **작업 목록(tasks)에 이름이 적힌 파일**을 처음 만드는 것은 허용한다(예: 비교 테스트를 실패 상태로 만드는 작업). 작업 목록에 없는 새 파일은 보호 폴더 안에서 만들 수 없다. `.claude/` 아래는 새 파일도 사람이 만든다(`settings.local.json` 포함). 만든 뒤 커밋한 파일은 보호 대상이 된다. 변환표와 매핑표의 기존 내용은 사람이 고치고, 에이전트는 추가할 줄을 제안만 한다. 단계별로 보호를 푸는 방법은 plan에서 정한다.
- **정답이 의심될 때**: 에이전트는 정답을 고치지 않고, 어느 행과 어느 컬럼이 왜 이상한지 적어 사람에게 보고하고 멈춘다.
- **검사 방법**:
  - 이미 커밋된 보호 대상의 Edit·Write를 PreToolUse 훅이 차단한다. 아직 없는 파일을 처음 만드는 것은 허용해야 하므로 deny로 일괄 차단하지 않는다(deny는 새 파일 생성도 막는다). 훅이 실패하거나 판단할 수 없으면 차단한다.
  - 훅의 "이미 커밋된 파일" 판단이 깨지지 않도록 에이전트의 git 명령은 읽기와 기록(`status`, `diff`, `log`, `show`, `add`, `commit`)만 허용한다. `rm`, `reset`, `restore`, `checkout -- 파일`, `stash`, `config`, `rebase`, `filter-*`와 `.git/` 접근은 차단한다. 되돌리기는 사람이 한다. 경로는 `realpath`로 실제 경로를 해석해서 판단하고, 링크·정션 생성은 차단한다.
  - 첫 커밋 직후 사람이 보호 대상 파일의 SHA-256 목록을 저장소 밖에 보관하고, 각 Phase 끝에 사람이 자기 터미널에서 대조한다. 에이전트는 이 목록을 보지 못한다. 훅이 뚫려도 이것으로 변경을 알 수 있다.
  - 작업 끝에 `git status`로 보호 대상에 의도하지 않은 변경이 없는지 확인한다.
  - 훅 시험 스크립트에서 보호 대상 수정 시도가 모두 막히는지 확인한다.

## 원칙 5. 테스트가 먼저 있고, 완료는 테스트 결과로 받는다

- **근거**: "다 됐어?"의 답은 에이전트의 말이 아니라 테스트 결과여야 한다. 정답과 한 행씩 비교하는 테스트가 있어야 구조 변경을 맡길 수 있다.
- **검사 방법**:
  - 비교 테스트를 실패 상태로 먼저 커밋한다.
  - 구현은 테스트 파일을 고치지 않는다.
  - 같은 실패는 오류 메시지를 읽고 원인을 한 줄로 적은 뒤 3회까지 고친다. 그래도 안 되면 멈추고 무엇이 막혔는지 보고한다.
  - 완료 보고에는 다음 네 가지가 붙는다.
    - 실행한 명령과 출력
    - 통과·실패 개수
    - 감사 결과(입력·출력 행 수, '확인 필요' 건수)
    - 변경된 파일 목록(`git status`)

## 변경 절차와 버전 규칙

- 원칙을 바꾸려면 근거와 검사 방법을 함께 고치고, 이 문서 맨 위의 버전과 날짜를 올린다.
- MAJOR: 원칙을 없애거나 뜻을 바꾼다. MINOR: 원칙을 더하거나 검사 방법을 크게 바꾼다. PATCH: 문장 수정이다.
- 이 헌법을 어기는 계획(plan)이 나오면 진행하지 않고 계획을 고친다.
