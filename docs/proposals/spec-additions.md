# spec.md 반영 제안 (Phase 3~6 구현에서 확정된 값)

`spec.md`는 보호 파일이라 제안만 합니다. 사람이 옮겨 적습니다. 기준은 현재 구현과 테스트(69개 통과, T043b·T043c 반영)입니다.
번호는 기존 마지막 번호(FR-020, NFR-010) 다음으로 이었습니다.

## A. 기존 문장 수정

**FR-011** 끝에 추가
> 출력 일자 셀은 날짜형이 아니라 `YYYY-MM-DD` 문자열이다.

**FR-016** 뒤에 추가
> 같은 설비 안에서 일자가 '확인 필요'이거나 비어 있는 행은 일자가 있는 행 뒤에 둔다.

**FR-019** 마지막 문장 교체
> 종료 코드는 0 정상, 1 일부 실패(열 수 없는 파일, 대응 규칙 없음 시트, 양식 모호 시트가 하나라도 있음), 2 전부 실패 또는 설정 오류다. 예외의 메시지와 종류는 출력하지 않는다.

**NFR-009** 마지막 문장 교체
> 파일명·시트명을 그대로 내는 옵션은 `--show-names`이며 사람이 켠다.

## B. 새 요구사항

- **FR-021 (값 정리)** 출력의 문자열 값은 앞뒤 공백을 뺀 값이다. 가운데 공백과 대소문자는 바꾸지 않는다. 설비·분류는 FR-009·FR-004의 변환 규칙을 적용한 값이다.
- **FR-022 (확인 필요 셀)** '확인 필요'인 컬럼의 셀에는 문자열 `확인 필요`를 쓰고, 원래 값은 '원래 값'에 FR-015 형식으로 남긴다. 해당 행의 다른 컬럼 값은 그대로 둔다.
- **FR-023 (출력 파일 이름)** `--out` 폴더에 `merged.xlsx`, `audit_<실행 시각>.txt`, `names_<실행 시각>.txt`를 만든다. `merged.xlsx`가 이미 있으면 `merged_<실행 시각>.xlsx`로 만든다. 어떤 기존 파일도 덮어쓰지 않는다. 읽은 파일이 하나도 없으면(전부 실패) 통합 파일은 만들지 않고 감사 결과와 이름 대응표는 만든 뒤 종료 코드 2로 멈춘다. (`tests/test_all_failed_audit.py`로 검증, T043b)
- **FR-024 (감사 결과 형식)** 감사 결과는 줄마다 `이름: 값` 형식이고, 다음 줄을 낸다. 셀 값은 나오지 않는다.
  - `입력 행 수`, `출력 행 수`, `행 수 일치`(예/아니오), `확인 필요 건수`, `중복 의심 건수`, `읽은 파일 수`
  - `처리 결과: 처리된 파일 없음`: 읽은 파일이 0개일 때만 낸다. 이때 입력·출력 행 수가 모두 0이라 `행 수 일치: 예`가 나오므로 정상 처리로 오해하지 않게 하는 줄이다. 정상 실행과 일부 실패에는 내지 않는다. (`tests/test_all_failed_notice.py`, T043c)
  - `실패한 파일`(없으면 `없음`)
  - `대응 규칙 없음 시트`, `양식 모호 시트`, `대응 중복 양식 시트`(FR-017의 한 표준 컬럼에 원본 컬럼이 여럿인 양식): 파일 표시명과 시트 표시명
  - `대응 규칙 없는 컬럼`: 파일, 시트, 컬럼 표시명(NFR-009)
  - `필수값 빈 칸`: 파일, 시트, 행 번호, 컬럼명
  - `숨긴 시트 수`와 파일별 `숨긴 시트`, `수식 값 없음 건수`, `수식 방지 접두사 처리 건수`
- **NFR-011 (통합 시트의 이름 노출)** 통합 시트의 '원본 파일'과 '원본 시트'에는 마스킹하지 않은 실제 이름이 들어간다. 통합 시트와 그 안의 셀 값은 입력과 같은 수준의 비밀로 다루고, 출력 폴더는 클라우드 동기화에서 제외한다(README의 보관 규칙). 로그와 감사 결과에 대한 NFR-009와 구분한다.

## C. 사람이 결정할 것

1. **NFR-007 구현 상태.** 지금은 `.xlsm`·`.xls` 거부만 구현되어 있고 크기·행 수 상한은 없습니다. 숫자가 정해질 때까지 spec의 `가정` 또는 `구체화 기록`에 "상한 미구현, 정보보호 부서 확인 대기(T003b)"를 적을지 정해 주세요.
2. **수용 기준 추가 여부.** US3에 "대응 규칙 없음/양식 모호 시트가 감사 결과에 나온다"는 기준과 "전부 실패해도 감사 결과가 남고 '처리된 파일 없음'이 적힌다"는 기준을 넣을지 정해 주세요. 앞의 것은 현재 US4-3에만 있고, 뒤의 것은 US3·'실패하는 경우' 절의 문장("모든 파일이 실패하면 통합 파일을 만들지 않고 실행을 멈춘다")에 "감사 결과는 남긴다"를 덧붙이는 것으로도 충분합니다.

## D. 해결된 항목 (참고)

- 전부 실패 때 감사 파일이 없던 문제: 구현을 바꿔 해결했습니다(T043b, 커밋 e472769).
- 전부 실패 때 `행 수 일치: 예`로 오해할 수 있는 문제: `처리 결과` 줄로 해결했습니다(T043c).
